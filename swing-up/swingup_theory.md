# 스윙업은 어떻게 동작하는가 — 에너지 펌핑에서 받기까지

[`README.md`](README.md)가 "무엇을 실행하나"를 다룬다면, 이 문서는 "왜 그렇게 하나"를 다룬다.
대상 코드는 [`swingup_control.py`](swingup_control.py)(실기)와
[`../simulator/rotary_swingup_realtime.py`](../simulator/rotary_swingup_realtime.py)(시뮬레이터) —
두 쪽 모두 같은 수식과 같은 숫자로 돈다.

---

## 1. 왜 밸런싱만으로는 못 세우나

극점 배치 밸런서는 직립점 근방의 **선형화** 위에서 설계된 것이다. 매달린 진자를 세우는 데
그대로 쓸 수 없는 이유가 세 가지 있다.

**① 직립점은 불안정하다.** 직립 기준 소각도에서 특성방정식은

$$s^2 + 2\zeta\omega_n s - \omega_n^2 = 0 \quad\Longrightarrow\quad s = -\zeta\omega_n \pm \omega_n\sqrt{\zeta^2+1}$$

판별식이 $\zeta^2 + 1 > 0$이라 감쇠와 무관하게 실근 두 개이고, 근의 곱이 $-\omega_n^2 < 0$이라
반드시 하나는 양수다. 동정값($\omega_n = 7.499$, $\zeta = 0.01172$)으로는
$s \approx +7.41,\ -7.59$ — 오차가 **135 ms마다 e배**로 커진다.

**② 유효 영역이 좁다.** 4-상태 밸런서가 회복할 수 있는 초기 기울기는 약 **31.5°**까지다
([`../simulator/rotary_plant_model.md`](../simulator/rotary_plant_model.md)). 매달림(180°)은
한참 바깥이다.

**③ 수평에서 제어 권한이 사라진다.** 플랜트의 입력 결합이 $b\cos\theta\,\ddot\phi$라서
$\theta = 90°$에서는 팔을 아무리 가속해도 진자에 직접 토크를 줄 수 없다. 매달림에서
직립까지 가는 길목마다 이 지점을 두 번 지나야 한다.

그래서 목표를 **각도가 아니라 에너지**로 바꾼다.

## 2. 플랜트 요약

$\theta$ = 직립 기준 진자 각도, $\phi$ = 팔 각도, 입력 $u = \ddot\phi$ (팔 각가속도 명령):

$$\ddot\theta = \frac{3g}{2l}\sin\theta + b\cos\theta\,\ddot\phi + \sin\theta\cos\theta\,\dot\phi^2 - 2\zeta\omega_n\dot\theta - F_c\,\mathrm{sgn}(\dot\theta)$$

$$\frac{3g}{2l} = \omega_n^2 = 56.24,\qquad b = \frac{3r}{2l} = 0.730$$

유도는 [`../rotary_bar_model/DERIVATION.md`](../rotary_bar_model/DERIVATION.md), 파라미터 동정은
[`../docs/pendulum_model_identification.md`](../docs/pendulum_model_identification.md) 참조.
스텝모터가 가속도 명령을 강제하므로 팔 방정식은 없다 — $\phi$는 자유도가 아니라 입력이다.

## 3. 에너지 좌표

직립 정지 상태를 0으로 하는 진자 에너지(질량 무관, $J$로 정규화):

$$E = \tfrac{1}{2}\dot\theta^2 + \frac{3g}{2l}(\cos\theta - 1)$$

| 상태 | E |
|---|---|
| 직립 정지 | $0$ |
| 매달림 정지 | $-2\,\omega_n^2 = -112$ |
| 펌핑 목표 | $+1$ (살짝 초과 — 받기 여유) |

이 한 숫자가 "꼭대기까지 얼마나 남았나"를 요약한다. 미분하고 무감쇠 운동방정식을
대입하면 중력항이 상쇄되고:

$$\dot E = \dot\theta\ddot\theta - \omega_n^2\sin\theta\,\dot\theta
= b\,\dot\theta\cos\theta\,\ddot\phi \;+\; \dot\theta\,\dot\phi^2\sin\theta\cos\theta$$

첫 항이 지배적이고 **직접 제어 가능한** 항이다. 여기서 전략이 그대로 나온다:

$$\ddot\phi \propto \mathrm{sgn}(\dot\theta\cos\theta) \quad\Longrightarrow\quad \dot E \ge 0$$

진자의 위상에 맞춰 팔을 미는 것 — 그네를 구를 때 다리를 타이밍 맞춰 젓는 것과 같은
원리다. (둘째 항은 원심 효과로, 제어 법칙에서는 무시하고 외란으로 취급한다.)

## 4. 펌핑 법칙

실제 swing 모드의 명령은 세 부분이다:

$$u = \underbrace{30 \cdot \mathrm{clip}\!\big(0.3\,(1 - E),\,0,\,1\big) \cdot \mathrm{sgn}(\dot\theta\cos\theta)}_{\text{에너지 조절 펌핑}} \;\underbrace{-\,3\phi - 5\dot\phi}_{\text{팔 붙들기}}$$

- **펌핑 크기 30 rad/s²** — 액추에이터 한계(47.1 rad/s²)의 64%. 세게 흔들수록 모터 전류가
  커지므로 여유를 남긴다.
- **$\mathrm{clip}(0.3(1-E), 0, 1)$** — $E$가 목표 $+1$에 다가가면 펌핑이 부드럽게 꺼진다.
  목표를 0이 아니라 $+1$로 잡는 이유: 정확히 0이면 꼭대기에 **정확히 정지**하며 도착해야
  하는데, 마찰이 조금만 다르면 못 미친다. 살짝 넘치게 올려서 받기 창을 통과시킨다.
- **$-3\phi - 5\dot\phi$** — 펌핑 자체는 팔 위치에 무관심해서, 이 항이 없으면 팔이
  150° 래치까지 표류한다.
- **시동**: 완전 정지에서는 $\mathrm{sgn}(\dot\theta\cos\theta)$가 정의되지 않으므로, 처음
  0.3 s는 개루프 킥(+30 → −30 rad/s², 각 0.15 s)으로 흔들림을 만든다. 시뮬레이터도 같은
  이유로 1° 기울여 시작한다.

## 5. 상태기계

```
        ┌──────────── fall: |θ| > 30° ────────────┐
        ▼                                          │
   ┌─────────┐     catch 조건 (셋 동시에)      ┌──────────┐
   │  SWING  │ ──  |θ| < 12°, |θ'| < 4 rad/s, ─▶│ BALANCE  │
   │ 에너지 펌핑│     |φ| < 60°                   │ 4-상태 u=−Kx│
   └─────────┘                                  └──────────┘
```

- **swing → balance**: 진자가 꼭대기 근처에 **느리게** 도착하고 팔이 중앙 근처일 때만
  전환한다. 셋 중 하나라도 아니면 한 바퀴 더 흔든다.
- **balance → swing**: $|\theta| > 30°$면 포기하고 다시 흔든다. 넘어뜨려도 다시 올라오는
  이유다.

## 6. 받기(catch)는 스냅이 아니라 핸드오프다

전환 순간에 두 가지 처리가 들어간다.

**팔 기준의 감쇠.** 잡힌 순간의 팔 각도를 $\phi_{\mathrm{catch}}$라 하면, 밸런서의 팔
기준값은 0이 아니라

$$\phi_{\mathrm{ref}}(t) = \phi_{\mathrm{catch}}\,e^{-t/3\,\mathrm{s}}$$

로 서서히 0에 접근한다. 전환 즉시 $\phi = 0$을 요구하면 — 팔을 옮기려면 진자를 먼저
반대로 기울여야 하는 **비최소위상** 특성 때문에 — 방금 잡은 진자를 도로 넘어뜨린다.

**온순한 극점.** 밸런서는 4-상태 피드백 $u = -Kx$, $x = [\theta, \dot\theta, \phi, \dot\phi]$:

$$\text{극점: } -6 \pm 6j \;(\text{진자 쌍}),\quad -1.5 \pm 1j \;(\text{팔 쌍})$$

$$K = [236.2,\; 26.5,\; -4.16,\; -4.55] \quad (\text{Ackermann, } \texttt{rotary\_model.place4})$$

진자 쌍이 자세를 잡고, 팔 쌍은 그보다 4배 느리게 팔을 데려온다. 극점을 더 공격적으로
($-10 \pm 10j$ 등) 잡지 않는 이유는 가속도 한계 47.1 rad/s²와 속도 한계 7.85 rad/s —
첫 보정에서 바로 포화되면 선형 설계가 무의미해진다.

## 7. 실기 제약 — 모터는 이상적 가속도원이 아니다

| 제약 | 값 | 결과 |
|---|---|---|
| 가속도 | ≤ 24000 pps² = 47.1 rad/s² | 펌핑·받기 보정의 상한 |
| 속도 | ≤ 4000 pps = 7.85 rad/s | 에너지 주입 속도의 상한 |
| 데드존 | < 30 pps면 모터 정지 | 저속 통과마다 팔이 끊김 (L6474) |
| 래치 | $\lvert\phi\rvert \ge 150°$ 영구 정지 | 케이블 보호 — 호스트는 140°에서 먼저 정지 |
| 루프 | 100 Hz, 읽기→명령 4 ms | 제어 주기의 거의 절반이 순수 지연 |
| 인코더 | 0.3° (1200 CPR) | 양자화 노이즈가 D 경로로 증폭 |
| 각속도 | 차분 + 10 ms 필터 | 속도 센서 없음 — 감쇠 경로에 추가 지연 |

시뮬레이터([`../simulator/rotary_model.py`](../simulator/rotary_model.py))는 이 전부를
모사한다 — `x` 키로 현실/이상을 전환해 보면 각 효과의 무게를 체감할 수 있다.

## 8. 펌웨어: `SwingupController/SwingupController.ino`

원래 펌웨어(AccelerationController)로는 밸런싱이 버티지 못했다. 세 가지를 고쳤다:

| 증상 | 원인 | 수정 |
|---|---|---|
| 명령의 ~40%가 씹힘 | 모터 회전 중 드라이버 위치 조회가 통신을 블록 | 회전 중엔 조회 금지, 보드가 직접 스텝 카운트 |
| 출발/방향전환마다 0.1 s 멈칫 | 모터 라이브러리의 상태기계 | 스텝 신호를 직접 생성 |
| 살짝만 쳐도 넘어짐 | 보수적 가속 한계 | 12000 → 24000 pps², 팔 가동범위 확대 |

업로드 체크리스트: 진자를 **매단 채 정지** 상태에서 업로드(부팅 자세 = 인코더 0°),
보드 `Nucleo F401RE` + STM32 코어, **X-NUCLEO-IHM01A1 정확히 1.0.1**(드라이버 내부
`device_prm`을 직접 사용), 디버그 버튼 금지, 업로드 후 Serial Monitor 닫기.
원본 AccelerationController는 그대로 둔다.

## 9. 수직은 켤 때마다 다른 곳에 있다

보드를 리셋할 때마다 인코더 영점이 **±1~2°** 틀어진다. 편향된 영점으로 균형을 잡으면
"직립"이 실은 작은 기울기라서, 그 기울기를 유지하려는 일정한 팔 가속이 팔을 래치 쪽으로
꾸준히 밀어낸다. 두 겹으로 해결한다:

1. **실행 전 보정** — 진자를 살짝 흔들어 **흔들림의 정중앙**을 진짜 수직으로 잡는다
   (`swingup_control.py`가 자동 수행, `--no-calibrate`로 생략 가능).
2. **균형 중 적응** — 팔이 표류하는 방향이 편향의 부호를 알려준다. 느린 추정기가 영점을
   교정한다(±5° 클램프). 시뮬레이션에서 +1.5° 주입 오차가 서 있는 동안 회복됨을 확인.

추정기가 **느려야** 하는 이유: 팔 신호를 밸런서의 팔 쌍($-1.5 \pm 1j$)과 공유하므로,
빠르게 적응하면 두 루프가 팔을 서로 잡아당긴다. 그래서 시상수를 수 초로 둔다.
시뮬레이터에서 `o` 키로 +1°씩 주입하며 회복을 관찰할 수 있다.

## 10. 검증

`python3 simulator/rotary_swingup_realtime.py --check`:

| 항목 | 결과 |
|---|---|
| 공칭 첫 받기 | **2.4 s** (실기 1.9~3.4 s) |
| 단일 모델 오차: $b$ ±20%, 건마찰 ×0.5~2, 지연 12 ms, 초기 기울기 ±2.5° | 전부 받고 균형 |
| 무작위 조합 24회 (위 범위 + 지연 4~12 ms) | **24/24 균형** |
| 인코더 영점 +1.5° | 서 있는 동안 회복 |
| 밸런싱이 버티는 최대 킥 | ~148 °/s |

실기 결과: 2~3초 만에 올라가서 서고, 쳐서 넘어뜨려도 다시 올라간다.

## 한 줄 요약

**직립은 불안정하고 선형 설계는 31.5°까지만 유효하므로, 매달림에서는 에너지를 목표로
$\mathrm{sgn}(\dot\theta\cos\theta)$ 방향으로 팔을 흔들어 $E$를 0까지 끌어올리고, 12° 창에서
4-상태 밸런서에게 부드럽게 넘긴다 — 팔 기준은 3초에 걸쳐, 인코더 영점은 수 초에 걸쳐,
각자 자기 시간축에서 정리한다.**
