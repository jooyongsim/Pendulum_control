# slides — lecture decks built from this codebase

Self-contained: everything needed to rebuild the deck is in this folder. The
numbers on the slides are recomputed from `../simulator/rotary_model.py` and
`../swing-up/balance_control.py` every time, so a deck cannot drift away from
the code it describes.

## Rebuild

```bash
cd Pendulum_control/slides

python place_figs.py                         # figures -> figs/
DECK_CONTENT=deck_content_place python build_pptx.py "상태피드백_이득설계_place4_LQR_AMSL.pptx" eq_png_place
```

On Windows PowerShell:

```powershell
$env:DECK_CONTENT = "deck_content_place"
python build_pptx.py "상태피드백_이득설계_place4_LQR_AMSL.pptx" eq_png_place
```

`build_pptx.py` asserts that no slide runs past the footer, so an overflowing
slide fails the build rather than shipping clipped.

## Files

| File | What it is |
|---|---|
| `build_pptx.py` | The AMSL deck builder. Reads a content module, writes the PPTX. |
| `render_eq.py` | Equation images, via matplotlib mathtext with the `cm` font set. |
| `deck_content_place.py` | This deck: where the controller lives, `place4`, `place2`, LQR. |
| `place_figs.py` | Its two figures, computed from the real `rotary_model`. |
| `figs/` | Generated figures. Regenerated by `place_figs.py`. |
| `eq_png_place/` | Generated equation images. Regenerated by `build_pptx.py`. |

## Writing a deck

A content module defines four names:

- `COVER` — `dict(title, subtitle, meta=[...])`
- `FOOTER` — the footer line
- `EQ` — `{key: mathtext string}`, rendered once each
- `SLIDES` — a list of slide dicts

A slide dict takes:

| Key | Meaning |
|---|---|
| `n`, `title`, `lead` | slide number, heading, one-line lead |
| `body` | list of `("eq", key)`, `("term", label, text)`, `("plain", text)` |
| `table`, `table2` | `dict(head=[...], rows=[[...]])`, stacked vertically |
| `figure` | `(filename_in_figs, caption)` |
| `red` | the takeaway line, set in red |
| `tail_eq` | an equation after the tables |
| `note` | small grey line at the bottom |

A `plain` or `term` line containing `$...$` is rendered as an image instead of
typed text, so inline maths survives.

## Equation constraints

Equations go through **matplotlib mathtext**, not real LaTeX. It has no matrix
environment and no `\boxed`, and `\text{}` cannot hold Korean. So:

- set matrices as a `table`, not as an equation (see slide 3)
- keep a space after `\int_0^\infty`, or it binds to the next letter
- write `\mathrm{...}`, not `\operatorname{...}`

`\frac`, `\dfrac`, `\prod`, `\mathcal`, `\dot`, `\ddot` and Greek all work.

## Requirements

`python-pptx`, `matplotlib`, `numpy`, `Pillow`. **scipy is not installed** in
this environment — `place_figs.py` integrates with its own RK4 rather than
calling `scipy.linalg.expm` for that reason.
